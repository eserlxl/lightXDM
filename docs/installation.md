# Installation

Everything `install.sh` does, every option, the two login modes, and uninstalling.

## Install from the AUR

```sh
yay -S lightxdm    # or: paru -S lightxdm
lightxdm-install   # as your regular user, not root
```

The [`lightxdm`](https://aur.archlinux.org/packages/lightxdm) package installs only the tool: the scripts and templates in `/usr/share/lightxdm`, these guides in `/usr/share/doc/lightxdm`, and four commands. It changes no setting by itself; pacman prints a note that tells you to run `lightxdm-install`.

| Command | Runs |
|---------|------|
| `lightxdm-install [options]` | `install.sh` with the same options: every `bash install.sh` command in this guide works as `lightxdm-install` |
| `lightxdm-update [--dry-run] [--non-interactive]` | `install.sh --update`: applies a newer lightXDM to your last install, leaving what you changed alone |
| `sudo lightxdm-uninstall [--keyring-only] [--dry-run [--json]]` | `uninstall.sh` (`--dry-run` previews changes without modifying anything and runs without sudo on readable files) |
| `sudo lightxdm-autologin <user>`, `sudo lightxdm-autologin --disable`, `lightxdm-autologin --status [--json]` | `enable-autologin.sh` |

A package update replaces only the files in `/usr/share/lightxdm`. Your dotfiles and the PAM lines change when you run `lightxdm-update`, which pacman reminds you of after each update. To remove lightXDM, run `sudo lightxdm-uninstall` first and `sudo pacman -R lightxdm` after it: removing the package alone leaves the setup in place, and reinstalling it brings `lightxdm-uninstall` back.

A util-linux update can leave `/etc/pam.d/login.pacnew`. If you take it over `/etc/pam.d/login` (for example with `pacdiff`), run `lightxdm-update` afterwards so lightXDM's keyring lines (and GNOME's session-type block) come back. The package installs a pacman hook (`/usr/share/libalpm/hooks/lightxdm-login-pacnew.hook`) that prints this reminder after each such update while the `.pacnew` waits; it only reads and changes no file.

## Quick Install (Arch Linux)
```sh
# Clone and run the installer
cd ~
git clone https://github.com/eserlxl/lightXDM.git
cd lightXDM
bash install.sh
# Or select a desktop explicitly (skips detection and prompt):
# bash install.sh --de i3
# Or review the package list for a desktop without installing anything:
# bash install.sh --list-packages --de i3
# Or preview the resolved installation without sudo or changes:
# bash install.sh --dry-run --de i3
# Or fail instead of prompting for sudo credentials (for unattended installs):
# bash install.sh --non-interactive --de i3
# Or configure an existing desktop without installing packages:
# bash install.sh --no-packages --de i3
# Or skip keyring packages and PAM keyring setup (for autologin or keyring-free setups):
# bash install.sh --no-keyring --de i3
# Or log in on TTY1 without a password (no keyring unlock) in the same run:
# bash install.sh --no-keyring --autologin --de i3
# Or create ~/.config/lightxdm/.xinitrc-<id> to customize before installing (no sudo):
# bash install.sh --init-template --de i3
# Or initialize a custom X11 template from its installed session entry:
# bash install.sh --init-template --de openbox --from-session /usr/share/xsessions/openbox.desktop
# Or initialize a custom Wayland template from its installed session entry:
# bash install.sh --init-template --wayland --de hyprland --from-session /usr/share/wayland-sessions/hyprland.desktop
# Or validate, create (if missing), and install a custom session in one command (--no-packages implied):
# bash install.sh --install-session /usr/share/wayland-sessions/sway.desktop
# bash install.sh --install-session /usr/share/xsessions/openbox.desktop --de openbox --dry-run
# Or create a custom Wayland template, edit it, then configure an installed compositor:
# bash install.sh --init-template --wayland --de sway
# bash install.sh --no-packages --de sway
# Or use KWallet for that custom session instead of GNOME Keyring:
# bash install.sh --no-packages --de sway --keyring kwallet
# Every script has a read-only help: bash install.sh --help, bash uninstall.sh --help, bash enable-autologin.sh --help
# Or inspect installed freedesktop session entries or current lightXDM state without sudo or changes:
# bash install.sh --preflight
# bash install.sh --preflight --json
# bash install.sh --doctor
# bash install.sh --doctor --json
# bash install.sh --recover --dry-run
# bash install.sh --recover
# bash install.sh --fix --dry-run
# bash install.sh --fix
# bash install.sh --login-mode autologin --dry-run
# bash install.sh --login-mode password --dry-run
# bash install.sh --dotfile-updates diff
# bash install.sh --dotfile-updates interactive
# bash install.sh --setup-shell auto   # manages ~/.zprofile or ~/.config/fish/config.fish
# bash install.sh --setup-gpg auto [--gpg-ssh] [--dry-run]   # configures ~/.gnupg/gpg-agent.conf pinentry-program
# bash install.sh --list-sessions
# bash install.sh --list-sessions --json
# bash install.sh --shell-snippet zsh   # or fish
# bash install.sh --status
# bash install.sh --status --json
# bash enable-autologin.sh --status [--json]
# bash uninstall.sh --dry-run [--json]      # or with --keyring-only
```

## What the installer does

Plasma, GNOME, and Budgie start on Wayland through `~/.wayland-session`, which `.bash_profile` runs on TTY1 in place of `startx`. These desktops do not install `xorg-server` or `xorg-xinit`. XFCE, LXQt, LXDE, MATE, Cinnamon, and i3 start with `startx` through `~/.xinitrc`. Before choosing GNOME, read its [session requirements and screen-lock limitation](#gnome-session-requirements).

- **Detects your installed DE** (Plasma, GNOME, Budgie, XFCE, LXQt, LXDE, MATE, Cinnamon, or i3), or pass `--de <id>` (`plasma`, `gnome`, `budgie`, `xfce`, `lxqt`, `lxde`, `mate`, `cinnamon`, or `i3`) to configure a specific desktop explicitly. One detected desktop is configured automatically; two or more prompt you to choose (or pass `--de <id>` to select non-interactively).
- If no DE is found (and `--de` is not passed), it **prompts you to choose one** to install.
- Installs the minimal required packages for your chosen DE, including the correct polkit agent:
  - polkit-kde-agent for Plasma, lxqt-policykit for LXQt
  - polkit-gnome for XFCE and i3, whose templates start it
  - nothing extra for GNOME and Cinnamon (built into the shell), Budgie (budgie-polkit-dialog), LXDE (lxpolkit from lxsession) and MATE (mate-polkit), which start their own
- Pass `--guided` (or `--guided --dry-run` for preview only) for an interactive first-run setup wizard without having to remember flags: it runs `--preflight` before invoking `sudo` (stopping on hard blockers), builds a menu from detected built-in desktops, discovered ready custom X11/Wayland `.desktop` sessions, and all 9 built-in desktops (highlighting GNOME's GDM screen-lock limitation), prompts for password+keyring (GNOME Keyring or KWallet for custom sessions) vs `--no-keyring` vs `--no-keyring --autologin`, offers `--setup-shell <zsh|fish>` when missing, prints the exact reproducible non-guided CLI command alongside a full `--dry-run` preview, and asks confirmation before running the installer (`--guided` accepts only optional `--dry-run`).
- Pass `--list-packages --de <id>` (`plasma`, `gnome`, `budgie`, `xfce`, `lxqt`, `lxde`, `mate`, `cinnamon`, or `i3`; combinable with `--no-keyring`) to print the package set `install.sh` would install, one per line, and exit 0 without needing `sudo` or changing anything—useful to review the packages beforehand or install them yourself before running `--no-packages`.
- Pass `--dry-run --de <id>` to preview the resolved desktop and template source, the file that saves your choices for `--update`, dotfile destinations (and removal of an existing Wayland launcher for X11), packages, PAM keyring additions and removals, GNOME session-type block, enabled display managers to disable, and whether TTY1 autologin would be enabled. It exits before privilege checks, never calls `sudo`, and writes no files. Standalone `--dry-run` requires `--de` (or pair `--dry-run` with `--guided`, `--install-session`, `--update`, `--pam-only --de <id>`, `--recover`, `--fix`, `--login-mode`, `--dotfile-updates`, `--setup-shell`, or `--setup-gpg` below); `--no-packages`, `--keyring`, `--no-keyring`, `--autologin`, `--setup-shell`, `--setup-gpg`, and `--gpg-ssh` apply as usual, including the custom-session requirements below. Decisions that depend on unreadable files show `unknown (needs root)`. Use it separately from `--list-packages` and `--init-template`.
- Pass `--non-interactive --de <id>` for unattended installation. Every sudo call fails immediately if credentials are unavailable, including if cached credentials expire during installation. Use cached credentials or passwordless sudo.
- Pass `--no-packages` (optionally with `--de <id>`) to skip all package installation when you already have the required packages. Before changing dotfiles, PAM or display managers, the installer checks session commands (also after package installation). For X11, `startx` and the plain command name in the selected template's last `exec ` line must be on PATH. For Wayland, every absolute path before the first option (a word starting with `-`) on that line must be executable, and a plain command name such as `sway` must be on PATH; `startx` is not required. Both command-name checks include `~/.local/bin` on PATH. Templates without a simple `exec` command skip the template-command check. Dotfiles, PAM and display manager setup then run.
- Pass `--init-template --de <id>` without sudo to create an editable template: a copy of the bundled template for a built-in id, or the i3 X11 template with the session id and `exec` command swapped for a custom one. It creates `~/.config/lightxdm/.xinitrc-<id>`, or `.wayland-session-<id>` for Plasma, GNOME, and Budgie. These user templates override the bundled templates. For a custom Wayland compositor, add `--wayland` as described below. Existing files are never overwritten.
- Pass `--install-session <path>` to perform custom session setup in a single idempotent command (`--no-packages` is implied): it parses and validates `TryExec`/`Exec` before privilege checks or home writes, infers Wayland mode when `--wayland` is set or `<path>` resides under `wayland-sessions/`, derives a custom id via the `.desktop` filename unless `--de <custom-id>` is given (refusing built-in ids and conflicting sibling templates), previews the template under `--dry-run` without writing `~/.config/lightxdm/` or calling `sudo`, and on live installs creates the template only if missing (preserving existing user templates on rerun) before installing dotfiles, PAM, and display-manager state. Combines with `--de <custom-id>`, `--wayland`, `--uwsm`, `--dry-run`, `--non-interactive`, `--keyring <gnome|kwallet>`, `--no-keyring`, `--autologin`, `--setup-shell <zsh|fish|auto>`, `--setup-gpg <gnome|kwallet|auto>`, and `--gpg-ssh`.
- `--install-session` and `--from-session` also take a session name instead of a path: an argument without a slash, with or without `.desktop` (`bash install.sh --install-session sway`, `bash install.sh --init-template --de x --from-session sway`), is looked up as `<name>.desktop` in the directories `--list-sessions` scans, in the same order (system then user `xsessions`, then system then user `wayland-sessions`); within one session type the first match wins. A name found both as an X11 and as a Wayland session is refused with the matching paths listed, and a name found nowhere is refused with the searched directories listed, both before any change. An argument with a slash is used as the literal path, as before, and so is a slash-less `*.desktop` file that exists in the current directory; use `./<name>.desktop` to make that explicit.
- Run `bash install.sh --list-sessions` (or `--list-sessions --json` for machine-readable JSON on stdout, without sudo) to scan `/usr/share/xsessions/*.desktop`, `/usr/share/wayland-sessions/*.desktop`, `${XDG_DATA_HOME:-~/.local/share}/xsessions/*.desktop`, and `${XDG_DATA_HOME:-~/.local/share}/wayland-sessions/*.desktop` (skipping `Hidden=true` and `NoDisplay=true`), check `TryExec`/`Exec` availability and `--from-session` compatibility, note any built-in id match, user scope, or existing user template, and print ready `init:` (`--init-template --from-session`) and `install:` (`--install-session` / built-in `--de`) commands for compatible entries.
- Add `--from-session <path>` to `--init-template --de <custom-id>` to initialize a custom template from an installed session entry, for example `bash install.sh --init-template --de openbox --from-session /usr/share/xsessions/openbox.desktop`. Only its `[Desktop Entry]` group is read: `Exec` supplies the command and arguments, and the first semicolon-separated `DesktopNames` entry supplies `XDG_CURRENT_DESKTOP` (the custom id is used when absent). `DESKTOP_SESSION` stays the custom id. For X11, the rest comes from the i3 template; add `--wayland` for a Wayland template, for example `bash install.sh --init-template --wayland --de hyprland --from-session /usr/share/wayland-sessions/hyprland.desktop`. `Exec` supports whitespace-separated literal arguments and whole double-quoted words, with shell characters preserved literally through Bash quoting. Field codes such as `%f` and `%U`, backslash escapes, single-quoted words, and incomplete or joined quotes are refused before creating a template. A missing or empty `Exec` is also refused. This flag requires a custom id and cannot be combined with installation options; existing templates are never overwritten. Add `--uwsm` to a Wayland `--init-template --wayland` or `--install-session` to start the compositor through uwsm (`exec uwsm start -- <command>`), which runs it as a systemd user unit so `graphical-session.target` user services (bars, notification daemons, portals) start and stop with the session; `--install-session` is refused and `--init-template` warns when `uwsm` is not installed.
- Pass `--keyring <gnome|kwallet>` with `--de <custom-id> --no-packages` to choose the PAM keyring backend for a custom session. The default is GNOME Keyring. Built-in desktops refuse this flag, as do `--no-keyring` and `--init-template` combinations; invalid combinations stop before privilege checks or changes.
- Pass `--no-keyring` (combinable with `--de <id>`, `--list-packages`, and `--no-packages`) to omit `gnome-keyring` and `kwallet-pam` from package installation and skip `/etc/pam.d/login` keyring setup. GNOME's separate session-type PAM block is still installed.
- Pass `--update` after updating lightXDM to apply the new version to the last finished install with its saved choices; it changes only what lightXDM installed and you left as it was. A finished install saves its desktop id, its `--no-packages` choice and the package list it asked for in `${XDG_STATE_HOME:-~/.local/state}/lightxdm/install-choices`, and `--update` reruns with them. It also saves the resolved keyring backend (`keyring=<gnome|kwallet>`) and `--no-keyring` choice (`no_keyring=<0|1>`), which `--login-mode` updates in place so `--update` keeps `--no-keyring` and `--login-mode password` remembers a custom session's keyring after autologin. It installs only the packages this lightXDM version adds to that list; a listed package that is not installed (you removed it) stays out, and `--update` prints the `sudo pacman -S --needed` command that would install it (installs from before the saved list get only that note). A display manager you enabled again stays enabled: `--update` names it with the `sudo systemctl disable` command that turns it off. The keyring choice comes from `/etc/lightxdm/pam-keyring`, where the installer records the backend it set up. If `/etc/pam.d/login` lost those lines to a `.pacnew` merge that took the new file (pacman reports the version util-linux ships, and it differs from lightXDM's backup `/etc/pam.d/login.lightxdm.bak`), `--update` says so, adds lightXDM's lines back and records that version in `/etc/lightxdm/pam-login-base`, so removing the lines by hand later is not taken for another merge. If you edited the file, or removed or commented out one or both of lightXDM's keyring lines yourself (removing both brings back your backed-up original or the recorded version), `--update` leaves it alone and prints how to add the lines back or to turn keyring unlock off for good: `uninstall.sh --keyring-only` removes the lines and the keyring record. GNOME's session-type block follows the same rule: `--update` puts it back only after such a merge and leaves a block you edited as it is, while `install.sh --pam-only --de gnome --no-keyring` adds only the block back on request. `--update` refreshes an older form of lightXDM's keyring line but never removes the other keyring backend's lines; only an explicit install that switches desktops does. Installs from before the record use the keyring lines active in `/etc/pam.d/login` instead (none means `--no-keyring`; a custom id keeps the backend found there). `--update` never changes autologin and combines only with `--dry-run` and `--non-interactive`; `uninstall.sh` removes the saved file and both records (`--keyring-only` keeps the merge record for GNOME's block). `--update` refreshes a home dotfile only while it is lightXDM's unchanged copy: what lightXDM last wrote there (recorded in `${XDG_STATE_HOME:-~/.local/state}/lightxdm/installed-dotfiles`), the current template, or a template an older lightXDM shipped. A file you edited or replaced with a symlink stays, and the current template goes beside it as `<file>.lightxdm-new` with a `diff -u` command to compare them; a file you removed stays removed, with the command that puts it back; on an X11 desktop an executable `~/.wayland-session` stays, with a note that it starts instead of `startx`. `--update` also refreshes any outdated `# >>> lightXDM TTY1 auto-start >>>` .. `# <<< lightXDM TTY1 auto-start <<<` managed block in `~/.zprofile`, `~/.config/fish/config.fish`, in-home `$ZDOTDIR` / `$XDG_CONFIG_HOME`, or `${XDG_STATE_HOME:-~/.local/state}/lightxdm/installed-shell-hooks` in place (keeping surrounding lines and permissions, while leaving unmanaged custom triggers untouched and warning without aborting on symlinks or incomplete markers). An explicit `install.sh` run still replaces a hand-edited `~/.bash_profile`, `~/.xinitrc` or `~/.wayland-session` and keeps your version only as `*.lightxdm-edited`, so keep shell settings in `~/.bashrc`, which lightXDM's `~/.bash_profile` reads, and session changes in your `~/.config/lightxdm/` template (`--init-template`), which every run uses instead of the bundled one; `--update` installs a changed template over lightXDM's unchanged copy.
- Pass `--dotfile-updates <diff|accept|dismiss|interactive>` (optionally with `--dry-run`, no `sudo`) to inspect or resolve pending `*.lightxdm-new` files written by `--update`: `diff` displays read-only diffs against your current dotfiles (`~/.bash_profile`, `~/.xinitrc`, `~/.wayland-session`, `~/.gpg-agent-*`, `~/.config/autostart/lightxdm-gpg-agent-tty.desktop`); `accept` validates launcher syntax (`bash -n`), preserves your edited file (`*.lightxdm-edited*`), installs each new template atomically with its expected mode (`644`/`744`/`755`), updates `installed-dotfiles` hashes, and removes `*.lightxdm-new`; `dismiss` removes `*.lightxdm-new` while leaving your dotfiles untouched; `interactive` walks each pending file with `[a]dopt / [k]eep current / [s]kip / [q]uit`. Symlinks, non-regular files, and unsafe parent directories are refused cleanly.
- Pass `--pam-only --de <id>` to add only lightXDM's lines to `/etc/pam.d/login`: the keyring unlock lines and, for GNOME, the session-type block (with `--no-keyring`, only that block). It installs no packages and leaves your dotfiles and display managers as they are, and in the saved choices records only the keyring it turned on, so `--update` keeps it; `--update` names this command when it leaves out lines you removed. `--dry-run` previews it, and it cannot be combined with `--autologin`, `--list-packages`, `--init-template`, `--setup-shell`, `--setup-gpg`, `--gpg-ssh`, or `--install-session`.
- Pass `--preflight` by itself (or `--preflight --json` for machine-readable JSON on stdout) before installing to check regular-user/sudo readiness, `pacman`/`systemctl` availability, pacman lock or stale/missing sync database (warning when `${PACMAN_DB_DIR:-/var/lib/pacman}/db.lck` exists or `sync/*.db` is older than 7 days or missing, recommending `sudo pacman -Syu`), `getty@tty1.service` mask state, enabled display managers, console keymap vs desktop keyboard layout (warning when `${VCONSOLE_CONF:-/etc/vconsole.conf}` `KEYMAP` neither extends `${X11_KEYBOARD_CONF:-/etc/X11/xorg.conf.d/00-keyboard.conf}` `XkbLayout` (trq for tr) nor is paired with it in systemd's kbd-model-map (uk for gb), suggesting `sudo localectl set-keymap <map>`), system locale generation (warning when `${LOCALE_CONF:-/etc/locale.conf}` names a locale that `locale -a` does not list, recommending uncommenting it in `/etc/locale.gen` and running `sudo locale-gen`), a systemd-homed account (warning for autologin), login shell compatibility (recommending `--setup-shell <zsh|fish>` alongside `--shell-snippet <zsh|fish>` when needed), existing recorded setup (`install-choices`), detected built-in desktops (`detect_de`, including GNOME's GDM screen-lock note), NVIDIA DRM modesetting on Wayland targets (warning when `${NVIDIA_DRM_MODESET:-/sys/module/nvidia_drm/parameters/modeset}` exists and reads N or 0, recommending adding nvidia_drm.modeset=1 to the kernel command line or /etc/modprobe.d), and ready custom X11/Wayland `.desktop` sessions (`detected_custom_sessions` in JSON), then suggest your next `--dry-run --de <id>`, `--install-session ... --dry-run`, `--update --dry-run`, or `--list-sessions` command without modifying files or calling `sudo`; exits `0` when ready and `1` on hard blockers.
- Pass `--doctor` by itself (or `--doctor --json` for machine-readable JSON on stdout) after installing to verify runtime boot health end-to-end without modifying files or calling `sudo`: active launcher presence and executable permissions (`~/.wayland-session` vs `startx` / `~/.xinitrc`), Wayland-vs-X11 precedence shadowing, template syntax and executable commands, login-shell TTY1 auto-start triggers (`bash`/`zsh`/`fish`), `~/.config/lightxdm/no-autostart` pause state and pending `*.lightxdm-new` updates, managed GPG agent pinentry/marker health (`~/.gnupg/gpg-agent.conf`), PAM keyring/`login.pacnew`/GNOME `pam_env` rules, default keyring/wallet configuration (`${XDG_DATA_HOME:-~/.local/share}/keyrings/default` and `${XDG_CONFIG_HOME:-~/.config}/kwalletrc`), and keyring `.so` module presence, `getty@tty1.service`, re-enabled display managers, TTY1 autologin conflicts (unreadable root-owned files soft-report `unknown (needs root)`), system locale generation (warning when `${LOCALE_CONF:-/etc/locale.conf}` names an ungenerated locale, recommending uncommenting it in `/etc/locale.gen` and running `sudo locale-gen`), and NVIDIA DRM modesetting on Wayland targets (warning when `${NVIDIA_DRM_MODESET:-/sys/module/nvidia_drm/parameters/modeset}` exists and reads N or 0, recommending adding nvidia_drm.modeset=1 to the kernel command line or /etc/modprobe.d); exits `0` when healthy and `1` with concrete recovery commands when an issue is found.
- Pass `--recover` (optionally with `--dry-run`, `--de <id>`, and/or `--setup-shell <zsh|fish|auto>`) without `sudo` when broken dotfiles or a 3-failure TTY1 crash loop (`~/.config/lightxdm/no-autostart`) leave you at a recovery prompt: it reads your saved `install-choices` desktop (or explicit `--de <id>`), validates template syntax and session commands before touching any file, preserves existing user edits into `*.lightxdm-edited*` backups, restores fresh session dotfiles (`644` `~/.bash_profile` and autostart desktop entry, `744` GPG helper, and `755` executable launcher `~/.xinitrc` / `~/.wayland-session`) and `installed-dotfiles` hashes, removes any X11-shadowing `~/.wayland-session`, cleans superseded `*.lightxdm-new` files, and clears `~/.config/lightxdm/no-autostart` plus `startx-attempts` without changing packages, PAM, or systemd.
- Pass `--fix` (optionally with `--dry-run`, `--non-interactive`, and/or `--de <id>`) to unify `--doctor` diagnosis and multi-layer remediation in one idempotent command: it validates templates, `~/.config*` directories, `installed-dotfiles` records, dotfile readability/regular-file safety, and shell-hook symlinks first, inspects home and readable PAM/systemd/display-manager state read-only without elevating prematurely (`--dry-run` prints planned steps without calling `sudo` or modifying files), preserves valid user-edited session dotfiles unless broken, shadowed, missing, or paused (delegating broken/paused home launchers and broken helper/`~/.bash_profile` symlinks to `--recover`), adds missing or refreshes outdated managed `zsh`/`fish` TTY1 shell hooks, requests `sudo` only when system PAM or systemd/display-manager state needs inspection or repair (aborts cleanly on failed `--non-interactive` sudo before modifying `$HOME`), restores missing/partial/`.pacnew`-dropped PAM keyring and GNOME session-type rules, unmasks/enables `getty@tty1.service`, disables conflicting display managers, and re-runs `--doctor` at completion.
- Pass `--login-mode <password|autologin>` (optionally with `--dry-run`, `--non-interactive`, and for `password` `--de <id>` / custom `--keyring <gnome|kwallet>`) to switch an existing installation cleanly between password login with PAM keyring unlock and passwordless TTY1 autologin without touching dotfiles, packages, shell hooks, or display managers: `autologin` verifies `getty@tty1.service` and user readiness before calling `uninstall.sh --keyring-only` (keeping GNOME's session-type PAM block and config) and `enable-autologin.sh`; `password` resolves the saved desktop and keyring backend (`--de` or `install-choices`, plus `--keyring` / `pam-keyring` / `gnome` for custom sessions), validates `/etc/pam.d/login` and `/etc/lightxdm/` safety before removing lightXDM's autologin drop-in, and restores PAM keyring rules (plus GNOME's session-type block when applicable).
- Pass `--setup-shell <zsh|fish|auto>` either by itself (with optional `--dry-run`, no `sudo`), combined with a normal install (`--de <id> --setup-shell auto`), or combined with `--recover`: it honors in-home `$ZDOTDIR` (`$ZDOTDIR/.zprofile`) and `$XDG_CONFIG_HOME` (`$XDG_CONFIG_HOME/fish/config.fish`), refusing out-of-home or traversal overrides, verifies `$HOME`, parent directories, and target rc file are not symlinks, treats `bash` under `auto` as a no-op, leaves existing unmanaged TTY1 triggers untouched without duplicating them, writes or updates a fenced `# >>> lightXDM TTY1 auto-start >>>` .. `# <<< lightXDM TTY1 auto-start <<<` block, and records non-default hook paths in `${XDG_STATE_HOME:-~/.local/state}/lightxdm/installed-shell-hooks`; `uninstall.sh` reads that record from the default `~/.local/state/lightxdm/` location—not a custom `XDG_STATE_HOME`—while also checking default or in-home `$ZDOTDIR`/`$XDG_CONFIG_HOME` paths to remove only lightXDM's fenced block while preserving all surrounding configuration.
- Pass `--setup-gpg <gnome|kwallet|auto|remove>` (with optional `--gpg-ssh` to include `enable-ssh-support`, and `--dry-run`) either standalone (no `sudo`) or combined with a normal install (`--de <id>` or `--install-session`, omitting `remove` and `--no-keyring --setup-gpg auto`): it validates `${PINENTRY_GNOME_BIN:-/usr/bin/pinentry-gnome3}` / `${PINENTRY_QT_BIN:-/usr/bin/pinentry-qt}` (requiring regular executable binaries on live runs) and in-`$HOME` `${GNUPGHOME:-~/.gnupg}/gpg-agent.conf` safety before touching files, resolves `auto` from active `--keyring`/`--de`, saved `install-choices`, readable `/etc/lightxdm/pam-keyring`, readable `/etc/pam.d/login` keyring modules, or detected desktops, preserves any existing unmanaged `pinentry-program` untouched, writes or updates a fenced `# >>> lightXDM GPG setup >>>` .. `# <<< lightXDM GPG setup <<<` block atomically (`0700` leaf directory on creation, `0600` config), strips only that fenced block with `remove` (removing `gpg-agent.conf` if no other settings remain), and reloads `gpg-agent` via `gpgconf --kill gpg-agent` on change (see [gpg-agent.md](gpg-agent.md)).
- Pass `--status` by itself (or `--status --json` for machine-readable JSON on stdout) to inspect your saved install choices and active session template, TTY1 launcher and pause/journal flags, login-shell TTY1 hook state (including in-home `$ZDOTDIR` and `$XDG_CONFIG_HOME`), GPG agent `pinentry-program` / `enable-ssh-support` state (`gpg_setup`), home dotfiles (including local edits and pending `*.lightxdm-new` updates), PAM keyring and GNOME session-type state (plus waiting `/etc/pam.d/login.pacnew` notices), `getty@tty1.service` and disabled display managers, and TTY1 autologin status without modifying files or calling `sudo`; unreadable root-owned files report `unknown (needs root)` for PAM/display-manager state (or `disabled` with a `Note: cannot read ...; run --status with sudo for an exact result.` hint for TTY1 autologin) in prose, and `unknown-needs-root` (or `block-present-needs-root` when only GNOME's conf file is unreadable) in JSON (`--json` requires `--status`, `--preflight`, `--doctor`, `--list-sessions`, or `--check-keyring`).
- When install choices are saved, `--status` also prints `Reproduce with: bash install.sh <args>`: the install command that makes the same choices on another machine (or keeps them in a dotfiles repo). For a custom desktop, copy its `~/.config/lightxdm/` template to the other machine first: the command names the desktop id, not the template. The arguments are the ones `--update` reruns with (`--de`, `--no-packages`, `--keyring` for a custom desktop, `--no-keyring`), plus `--autologin` when your lightXDM TTY1 autologin drop-in is active and keyring unlock is off, `--setup-shell <zsh|fish>` when the shell hook state is managed, and `--setup-gpg <backend>` (plus `--gpg-ssh` when ssh support is on) when the GPG block is lightXDM-managed. `--status --json` carries the same list as `install_choices.reproduce_args` (`null` when no install choices are saved).
- Pass `--shell-snippet <zsh|fish>` by itself to print the canonical non-bash TTY1 auto-start block for `~/.zprofile` or `~/.config/fish/config.fish` cleanly on stdout without `sudo` or file modifications (for example `bash install.sh --shell-snippet zsh >> ~/.zprofile`); [startx-autologin.md](startx-autologin.md) documents the same blocks.
- `--no-polkit-rule` is still accepted for older scripts but has no effect: lightXDM installs no Polkit rule.
- Copies dotfiles to your home: `.bash_profile`, the session template as `~/.xinitrc` (X11 sessions) or `~/.wayland-session` (Wayland sessions, including custom compositors), the gpg-agent helper (`~/.gpg-agent-kwallet` for Plasma, `~/.gpg-agent-gnome` otherwise), and `~/.config/autostart/lightxdm-gpg-agent-tty.desktop`, which refreshes gpg-agent's display inside the session ([gpg-agent.md](gpg-agent.md)); `uninstall.sh` removes it like the other dotfiles.
- Appends PAM lines to `/etc/pam.d/login` (unless `--no-keyring` is passed; after a one-time backup at `/etc/pam.d/login.lightxdm.bak`; installing another desktop or choosing a different backend replaces the keyring lines lightXDM added for the previous one, and `uninstall.sh` removes the lines lightXDM added and restores the backup when nothing else changed, otherwise it keeps your other edits and leaves the backup for review) for keyring auto-unlock: KWallet (`pam_kwallet5.so`) for Plasma and custom sessions with `--keyring kwallet`, GNOME Keyring (`pam_gnome_keyring.so`) otherwise.
- For GNOME only, inserts a [session-type PAM block](#gnome-session-requirements) before the first session line, including with `--no-keyring`.
- Installs no Polkit rule: systemd already allows power-off, reboot, suspend, and hibernate in an active local session (`uninstall.sh` removes the `49-nopasswd.rules` older versions installed), while USB mounting uses `udisks2` defaults.
- Your DE will start automatically on TTY1 after login—no need to run 'startx'. The installer (including `--dry-run`) refuses before changing anything when `getty@tty1.service` is persistently masked or disabled (`--update` leaves a disabled one as it is and continues, since it hands nothing over); run `sudo systemctl unmask getty@tty1.service` or `sudo systemctl enable getty@tty1.service` and re-run the installer.

### Custom sessions

Custom ids use `~/.config/lightxdm/.wayland-session-<id>` when present, otherwise `~/.config/lightxdm/.xinitrc-<id>` for X11. If both exist, the installer refuses before making changes and names both files; keep only the template you want. Custom ids must contain only lowercase ASCII letters, digits, `_` and `-`, with no leading hyphen. They require `--no-packages`: install the compositor or window manager and its dependencies yourself. PAM uses GNOME Keyring by default (also selectable with `--keyring gnome`), or choose `--keyring kwallet` for KWallet. Install the matching `gnome-keyring` or `kwallet-pam` package yourself; the installer warns if its PAM module is missing. Pass `--no-keyring` to skip keyring setup instead.

Before changing dotfiles, PAM or display managers, `install.sh` checks a Bash template's syntax with `bash -n` without executing it.

For example, create and edit a Sway template, then install it:

```sh
bash install.sh --init-template --wayland --de sway
# Edit ~/.config/lightxdm/.wayland-session-sway as needed.
bash install.sh --no-packages --de sway
# To unlock KWallet for KDE applications in this session (install kwallet-pam first):
bash install.sh --dry-run --no-packages --de sway --keyring kwallet
bash install.sh --no-packages --de sway --keyring kwallet
```

`--wayland` is accepted only with `--init-template` and a custom id, or with `--install-session`. Plasma, GNOME, and Budgie already have Wayland templates; the six built-in X11 ids also refuse this flag. The generated file has mode `755`, exports `DESKTOP_SESSION=<id>`, `XDG_CURRENT_DESKTOP=<id>` and `XDG_SESSION_TYPE=wayland`, sources `~/.gpg-agent-gnome` when present, loads `~/.config/environment.d` variables via systemd's `30-systemd-environment-d-generator` when available (unless `--uwsm` is used, where uwsm imports them), and ends with `exec <id>` (or `exec uwsm start -- <id>` with `--uwsm`). A compositor that does not run XDG autostart entries needs `gpg-connect-agent updatestartuptty /bye` in its own startup, or SSH passphrase prompts go to TTY1 ([gpg-agent.md](gpg-agent.md)). Edit that line if the executable differs from your id, for example `exec Hyprland` for a `hyprland` id. A missing plain command stops installation before configuration. For custom X11, use `--init-template --de dwm` and then `--no-packages --de dwm` instead.

### Session files and backups

The Wayland templates in `dotfiles/` are copied to `~/.wayland-session` and end with:

| Desktop | Template | Session command |
|---|---|---|
| Plasma | `.wayland-session-plasma` | `exec /usr/lib/plasma-dbus-run-session-if-needed /usr/bin/startplasma-wayland` |
| GNOME | `.wayland-session-gnome` | `exec /usr/bin/gnome-session` |
| Budgie | `.wayland-session-budgie` | `exec /usr/bin/startbudgielabwc` |

An executable `~/.wayland-session` takes precedence over `startx`. Installing an X11 desktop after a Wayland one moves that file aside like `~/.xinitrc`, preserving an original as `~/.wayland-session.lightxdm.bak` or saving later edits as `~/.wayland-session.lightxdm-edited*`, then removes `~/.wayland-session` so `startx` can run. This also applies to edited or foreign session files. `uninstall.sh` restores the original backup; saved edits remain available for review.

### GNOME session requirements

**GNOME cannot lock the screen without GDM.** GNOME shows “Screen Lock disabled — Screen Locking requires the GNOME display manager”. lightXDM disables GDM, so choose GNOME only if you accept this limitation.

GNOME Shell runs as a systemd user service and needs a logind session of type `wayland`, but a getty login creates a `tty` session. For GNOME only, the installer inserts this block before the first session line in `/etc/pam.d/login` (`<installing user>` is replaced with your username):

```text
# lightXDM: GNOME on TTY1 needs a wayland session type (uninstall.sh removes this)
session    [success=2 default=ignore] pam_succeed_if.so quiet tty notin tty1:/dev/tty1
session    [success=1 default=ignore] pam_succeed_if.so quiet user != <installing user>
session    optional   pam_env.so readenv=0 user_readenv=0 conffile=/etc/lightxdm/gnome-session-type.conf
```

The first two lines after the comment skip the environment setting for other TTYs or users. `/etc/lightxdm/gnome-session-type.conf` sets `XDG_SESSION_TYPE DEFAULT=wayland`, so the block applies only to the installing user on TTY1. It is installed even with `--no-keyring`, independently of the `pam_gnome_keyring.so` lines that unlock GNOME Keyring for GNOME and Budgie.

Installing another desktop or running `uninstall.sh` removes the block and `/etc/lightxdm/gnome-session-type.conf`. `uninstall.sh --keyring-only` keeps both so GNOME can still start.

### Two Login Modes
1. **Default (Password Login + Keyring Auto-Unlock):** Type your password on TTY1; the desktop starts automatically and the keyring unlocks through PAM (KWallet on Plasma and custom sessions with `--keyring kwallet`, GNOME Keyring otherwise).
2. **Optional Autologin (`enable-autologin.sh`):** Run `sudo bash enable-autologin.sh YOURUSER` (`--disable` to revert; changes apply at the next login or reboot) to log in on TTY1 without a password; `bash enable-autologin.sh --status` (or `--status --json` for structured JSON on stdout) shows the current state without sudo. Because login happens without a password, PAM cannot unlock the keyring automatically—the keyring stays locked and asks for its password in the desktop unless its password is empty (`enable-autologin.sh` prints this warning when PAM keyring lines are configured). Pass `--no-keyring` to `install.sh` (combinable with `--de <id>` and `--no-packages`) to skip installing `gnome-keyring` / `kwallet-pam` and skip adding keyring lines to `/etc/pam.d/login`—recommended for autologin users who do not use a keyring and for window-manager setups without one. If keyring unlock is already set up, `bash install.sh --login-mode autologin` removes only lightXDM's PAM keyring lines and enables TTY1 autologin in one step (keeping GNOME's session-type block, dotfiles, and display managers untouched; `bash install.sh --login-mode password` switches back to password login with PAM keyring unlock). Manually, `sudo bash uninstall.sh --keyring-only` removes only the keyring lines lightXDM added to `/etc/pam.d/login` and leaves everything else in place. On a new install, `bash install.sh --no-keyring --autologin` skips the keyring setup and enables autologin in one run: it calls `enable-autologin.sh` for you after the rest of the install succeeds (`--autologin` refuses to run without `--no-keyring`).

After logging in, run `bash install.sh --check-keyring gnome` (or `--check-keyring gnome --json` for structured JSON on stdout) in a terminal inside the desktop, without sudo or other options (use `kwallet` on Plasma and custom sessions installed with `--keyring kwallet`, or `auto` to pick the backend as `--setup-gpg auto` does and print it on stderr). It reports the collection's current state: exit code **0** means unlocked, **1** means locked, and **2** means unavailable with the reason (for example, no secret service, collection or session bus). The check asks for no password, starts no service and changes nothing.
